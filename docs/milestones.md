# Colink 里程碑任务清单

> 依据：`docs/project-proposal.md`（产品方案、分期与里程碑、评价指标）  
> 对照：当前代码 `v0.1.0`（离线课表原型）  
> 粒度：**史诗（Epic）→ 用户故事（Story）→ 验收标准（AC）**  
> 用途：按周排期、阶段验收、长期维护

---

## 0. 使用说明

### 如何用这份清单

1. **排期**：按阶段总览表确定当前所处阶段；在阶段内按 Story 优先级（P0 → P1 → P2）拉任务。
2. **拆周**：每个 Story 的「建议周期」是理想工作量参考，可合并/拆分到迭代，但 **P0 Story 不可跳过**。
3. **验收**：Story 只有在全部 AC 勾选通过后才算 Done；模糊体验项写成可观察行为。
4. **依赖**：史诗标注「前置」的，未完成前不得开始下游 P0 项（尤其 E1.7 服务端之于阶段二）。
5. **变更**：范围变更须更新本文件的阶段退出标准与指标映射，而不是只改排期。

### 优先级定义

| 级别 | 含义 |
|------|------|
| P0 | 阶段退出必需，缺失则阶段不能关闭 |
| P1 | 影响核心指标或体验，阶段内应完成，可有明确延期理由 |
| P2 | 增强项，可移入下阶段 |

### Done 总定义

- 功能行为满足 AC（含边界与错误路径）
- 涉及持久化的数据可查询、可删除/导出（符合隐私要求）
- 有对应测试或人工验收记录
- 不引入未声明权限、不把资料明文外传
